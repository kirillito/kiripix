# M1: room export and the Manifest

Spec §9 and ADR 0003. docs/versions.md (Godot 4.7). User stories 23 and 24 of [0010](0010-m1-room-end-to-end.md).

## What to build

- Ops (`geometry`): contour trace, Douglas–Peucker simplify with a pixel tolerance, polygon to collision shapes, and a
  navigation polygon. Pure, golden-tested.
- The room's `export` Stage and `kiripix export <id>`: writes, under `export.godot.root`, the palette-mapped PNG and a
  scene with a `Sprite2D` Plate, a `StaticBody2D` with `CollisionPolygon2D`s from `solid`, a `NavigationRegion2D` from
  walkable ∩ reachable, `Marker2D`s for Spawns and Exits (with metadata: IDs and targets), `PointLight2D`s from light
  Markers, and `GPUParticles2D` stubs from emitter Markers. Each generated text file starts with
  `; generated by kiripix, do not edit`.
- The Manifest: one file per Asset under the export root, with the Asset ID, every exported ID, the files with their
  hashes, the "exported" flag, the counter, its `schema_version` and the Kiripix version. Export takes the project
  lock while writing it.
- Ownership: a file is overwritten only if the Manifest lists it with a matching hash; otherwise export refuses and
  names the file. The `--force` and `--adopt` paths are [0022](0022-m1-export-ownership-and-id-freeze.md). Godot's
  `.import` sidecars are ignored. Without the Godot project at `export.godot.project`, export refuses.
- Re-exporting an unchanged room writes nothing and leaves the counter alone.

## Acceptance criteria

- [ ] Golden tests for contour and simplify on a Mask with a hole.
- [ ] Exporting a reached room into a temporary Godot project folder writes the scene, the PNG and the Manifest, and
      the scene's text has the expected nodes and IDs.
- [ ] Editing the exported scene by hand, then exporting again, refuses and names the file.
